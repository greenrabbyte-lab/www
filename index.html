Le cas Linky

La maison joue l'on-prem. Rien n'en sort, sauf des kWh agrégés.

Un compteur Linky, des panneaux solaires, une VM de collecte sur la box, un PC avec un GPU pour le calcul et un modèle de langage local. Les données brutes et le modèle restent à la maison. Ce qui part vers le cloud est une couche « partage » (kilowattheures par jour et par heure, par appareil), contrôlée avant envoi et journalisée.

Collecte

Le compteur est lu en temps réel ; la VM de la box stocke les mesures et sert les tableaux de bord de la maison.

Calcul

Chaque nuit, le PC de calcul copie les jours complets, transforme (dbt sur DuckDB) et explique la consommation : appareils, nuit, prévisions.

Contrôle et envoi

Un contrôle refuse tout fichier hors contrat ou ressemblant à une donnée personnelle, puis un geste volontaire envoie la couche partage vers un stockage Azure, avec manifeste.

Application nomade

Un conteneur sans secret ni base, qui lit la couche partage et répond en moins d'une seconde. Déployable n'importe où.

En production, le rôle du contrôle avant envoi est tenu par un outil de classification des données (type Purview) ; ici, il est minimal, versionné et testé, et chaque envoi emporte son rapport.

La golden path

Quatre minutes, aucune équipe sollicitée : leurs règles étaient déjà dans le chemin.

Le portail

Dans Port.io, le développeur demande une fonctionnalité ; le risque faible est validé seul, sans ticket.

Le bac à sable

« Obtenir mon bac à sable » : une VM Terraform apparaît (sans IP publique, arrêt automatique à 19 h, budget), avec Claude Code et les compétences de l'équipe déjà installées.

Le travail

Un prompt : « ajoute une carte, un test, pousse le code, ouvre une pull request ». Claude Code code, teste (JUnit), pousse.

Le pipeline

Tests, analyse de sécurité de l'image, aperçu, double validation métier et plateforme, puis déploiement par la plateforme seulement.

Ce qui tient debout

La vitesse vient d'une chaîne qui bloque, pas d'une confiance aveugle.

Des releases qui prouvent

Chaque release de production embarque le rapport de failles, la nomenclature logicielle (SBOM) et les exceptions datées. Les images sont signées et déployées par empreinte.

Une porte, trois paliers

L'IA passe par les mêmes portes que tout le monde : un compte sans privilège, une commande unique qui journalise chaque action, un retour arrière écrit et prouvé pour chaque type d'action. Les secrets restent hors de sa portée.

journal en ajout seul · plan annoncé avant apply

Un journal des erreurs

Chaque erreur de l'IA ou de la chaîne est consignée avec sa release, sa gravité, qui l'a détectée et le correctif. Le taux d'erreur par release est un tableau de bord, pas un secret.
